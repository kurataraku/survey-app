# 学校提携のセットアップ

1. 検証用の既存データベースに `supabase-migrations/create-school-partnerships.sql` を適用する。学校側のログインは別のSupabaseプロジェクトを作り、メインのデータベースとは別のプロジェクトURLとキーを `.env.example` の学校認証欄に設定する。
2. 学校認証プロジェクトのメール認証を有効にし、一般ユーザーの新規登録は無効にする。Magic Linkのメール本文に `{{ .Token }}` の認証コードを表示する。学校のアドレスへ配信できるSMTPとTOTP認証を有効にする。運営は既存の認証プロジェクトのTOTPを使う。ログイン・登録には担当者個別の業務用メールアドレスを用いる。
3. 新着・掲載停止・招待の案内に既存のResend設定 `EMAIL_SERVICE`、`EMAIL_API_KEY`、`EMAIL_FROM` と、メール本文のリンク用に `NEXT_PUBLIC_SITE_URL` を使用する。運営用のGA4集計には `GA4_PARTNERSHIP_PROPERTY_ID`、`GA4_PARTNERSHIP_STREAM_ID` と、対象プロパティの閲覧権限があるGSCサービスアカウントを設定する。
4. 運営管理の学校編集ページから「この学校の提携・資料請求を管理」を開き、学校担当者を招待する。運営法人名と学校の閲覧期限を設定する。公式URLは学校編集画面で確認・保存する。各校について、担当者がログインして二要素認証を登録できることを確認してから、機能を有効にする。
5. 検証用の学校A・Bを使い、架空の宛名・住所・電話番号で、受付、運営による公開、新着通知、自校分の閲覧、確認、発送済み登録まで通す。Aでログインした状態でBの受付番号を直接指定した場合と、停止された担当者が詳細を再取得した場合に拒否されることを確認する。写真・メッセージの保存、停止通知、修正版の再公開も確認する。

本番の最初の学校を有効にする前に、学校側と通知先、電話番号の利用目的、発送目安、閲覧期限を確定する。学校の画面における閲覧期限は、運営データベースから請求を削除する期限とは別に扱う。運営が保管する受付データと提供記録についても、運用上の保管・削除手順を決める。
